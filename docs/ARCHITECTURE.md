# Architecture

```
 source (MiniC)
      |
      v
 Stage 1  frontend/        lexer -> parser -> UnifiedSemanticVisitor
      |                    (name resolution, type check, constant propagation,
      |                     folding, strength reduction, branch/loop pruning,
      |                     SSA-friendly IR, diagnostics with recovery)
      v   LLVM IR
 Stage 2  stage2/          52 metrics (llvmlite binding walk, dominators, loops)
      |                    CostBenefitGate: run pass p only if B > lambda*E + mu*T
      v
 Stage 3  compile_pipeline.py
      |   -Meco       gate(eco) over every optional pass
      |   -Mbalanced  XGBoost ranker (stage3_ml_model.py) -> gate(balanced)
      |   -Mperf      genetic search (ml_models/ga.py)     -> gate(perf)
      v
 backend/passes.py        LLVM new pass manager, per-pass timing, verification
      v
 energy/execution.py      object_bytes (code generation), JIT for differential checks
 backend/native.py        link the object, run it, time it with native_harness.c
```

## Two front-end pipelines, on purpose

`frontend/codegen.py` plus `frontend/semantic_checker.py` form the
**conventional** pipeline: parse, a separate checking walk, a second walk that
emits IR with no simplification. `frontend/semantic_codegen.py` is the
**unified** pipeline. The energy experiment compares them, and the differential
tests require identical results from both on every program.

The unified visitor lowers each node to a `TypedValue(type, value, const,
effects)`. All arithmetic goes through `SimplifyingIRBuilder`, which counts
what it avoids (`folded`, `identities`, `strength_reductions`); statistics are
returned with the IR and shown in the logs.

## Gate

`stage2/pass_gating.py` evaluates `B > lambda*E + mu*T` per pass with
`(lambda, mu)` set by the budget (`eco`, `balanced`, `perf`). `B` is the
predicted benefit (static-cost reduction x per-unit run energy), `E` and `T`
come from measured per-pass profiles (`profiles/per_pass.json`, regenerated by
`ml_models/collect_dataset.py`). Every decision is returned with a reason and
shown in the UI's Gate tab.

## Data flow of one compilation

`compile_source(source, mode)` returns a dict that the CLI prints and the API
serialises: IR before and after, gating log, per-stage seconds and joules,
baseline and optimized runtimes, lifecycle EDP and break-even, the GA record
(history, finalists) and the object file path.

## API

| endpoint | purpose |
|---|---|
| `POST /compile` | `{source_code, mode, n_runs}` -> full result |
| `GET /benchmarks`, `/benchmarks/<name>` | bundled kernels and sources |
| `GET /benchmark-results` | `reports/benchmarks/results.json` and chart names |
| `GET /reports/benchmarks/<file>` | chart images |
| `GET /health` | liveness |

## Tests

`tests/` covers the lexer/parser/semantics, numeric folding against C, both
pipelines on every benchmark and mode (including native exit codes), Stage-2
metrics, gating, the energy harness math with a fake counter, the meter,
lifecycle accounting, the GA objective, the ranker's labels and leave-one-out
evaluation, and the API contract. Tests redirect the per-pass profile and the
model cache to a temporary directory, so running them never rewrites tracked
data.
